# 留存口径取舍备忘：下一版可加的一类聚合记录

范围：只分析，不改 `greenbook` 包、不加 CLI、不写仓库内数据库、不回溯重发历史。
下面所有数字都由现有入口 `python3 -m greenbook preview` 在仓库样本上跑出，可用
`python3 -I retention/check.py` 复现（末尾自带断言）。

## 0. 结论

现行对外投影（每个固定 50 ms 桶：各相位的确定服务毫秒 + 各探头按接线相位计的有证在线毫秒）
**不足以**判定“某探头在该相位确定绿窗内的重叠毫秒是否达到最低观察时长”。
用同一份投影可以构造两个合法输入，在同一桶、同一阈值下一过一不过（第 2 节）。

建议下一版新增**一类**聚合记录：`(桶, 接线相位, 探头, 接线段)` → `确定绿毫秒 / 有证在线毫秒 / 重叠毫秒`。
两种候选口径中选**按接线段分段（口径 B）**：它比相位合并（口径 A）只多 0–1 行，却能把
“换接前 / 换接后 / 接回同一相位”分开，并且可原样求和回口径 A。

## 1. 记号

对桶 `B = [lo, hi)`、相位 `p`、探头 `d`：

- `a = |G_p ∩ B|`：相位 `p` 的确定服务窗（`services[].certain`）在桶内的并集长度；
- `b = |C_{p,d} ∩ B|`：探头 `d` 在接线相位 `p` 下的有证在线窗（`coverage[].time_ms`，
  已与接线、心跳、可信时钟相交）在桶内的并集长度；
- `o = |G_p ∩ C_{p,d} ∩ B|`：复盘员真正要的重叠毫秒。

现行投影只交 `a` 和 `b`（按相位、按探头）。它不交 `o`。

## 2. 两份合法输入：投影完全相同，判定相反

`retention/alpha.json` 与 `retention/beta.json` 都由 `examples/baseline.json` 派生：
把 `buckets` 换成 `[0,700)` 上的 14 个 50 ms 桶，其余不动（alpha）；beta 只改 `heartbeats`
里 `h1`、`h2` 的 `ticks`（`[10,61]→[0,13]`，`[59,310]→[21,310]`）。两份都通过
`preview` / `publish` / `replay`（退出码 0），是合法输入。

在桶 `b000 = [0,50)`、相位 `N`、探头 `loop`：

| 输入 | 确定绿 `a` | 有证在线 `b` | 重叠 `o` | `T=30 ms` |
|---|---|---|---|---|
| alpha | 38 | 39 | **38** | 过 |
| beta | 38 | 39 | **28** | 不过 |

两份输入的对外投影逐字节相同（harness 摘要 `41b9da76bbed0347`），`services` 也相同；
差别只在 `coverage`：

- alpha：`loop/N` 覆盖为 `[11,60)`、`[60,250)`（桶内 39 ms 中有 38 ms 落在绿窗 `[12,50)`）；
- beta：覆盖为 `[1,12)`、`[22,250)`（其中 11 ms 落在绿窗之前 → 28）。

再补一份 `retention/gamma.json`（同投影，覆盖为 `[0,23)`、`[34,250)`），重叠取到
**下界 27**。于是同一组 `(a,b)=(38,39)` 可以对应 `o = 38 / 28 / 27`，即上下界都能取到。

同样地，`retention/shift-a.json` / `shift-b.json` 反向证明 `services` 也不被投影决定：
两者投影相同（`486369d75ee292ec`），`coverage` 相同（`[0,10)`、`[40,50)`），但确定绿窗
分别是 `[10,30)` 和 `[30,50)`（都在桶内、都为 20 ms），`o` 分别为 0 和 10。
所以“用完整产物的 `services` 和 `coverage` 校核”这句话里，两者各自都可能藏住差异。

## 3. 旧投影能给出的界限，以及它为什么到顶

由 `G∩C ⊆ B` 直接得

```
max(0, a + b - |B|)  ≤  o  ≤  min(a, b)
```

对 `b000/N/loop` 就是 `[27, 38]`。这个区间是**紧的**：alpha 取到上界 38，gamma 取到下界 27。
因此不存在只依赖 `(a, b, |B|)` 的更强估计——旧投影的信息量到此为止。

可判的只有区间外：`T ≤ 27` 必过，`T > 38` 必不过。**`T ∈ (27, 38]` 一律不可判**，
包括 `T=28,29,30,38`。这正是第 2 节一过一不过的阈值区。

## 4. 三种追问的核对

### 4.1 合并相邻整桶

若只保留每桶总量，合并时**必须把 `o` 相加**，不能对合并窗口重算 `a+b-|B|`：

| 输入 | 14 桶 `sum(o)` | `[0,700)` 精确 `o` | 逐桶界求和 | 合并窗界 |
|---|---|---|---|---|
| alpha | 134 | 134 | `[123,134]` | `[0,239]` |
| beta | 124 | 124 | `[123,134]` | `[0,239]` |

原因：`o` 对窗口的任意划分可加；而 `a+b-|B|` 不可加，合并后迅速退化成 `[0,239]`。
在 `T=130 ms`：真值 alpha 过、beta 不过；旧数据无论用逐桶界求和（`[123,134]`）
还是合并窗界（`[0,239]`）都**不可判**。注意入口目前不强制桶构成划分——重叠桶、留空隙、
不等宽的 `buckets` 都会被照收（见 `check.py` 的 F2 段），所以网格本身要在新记录里显式带上。

### 4.2 换接前后，含接回同一相位

`reattach.json` 与 `reattach_r2.json` 都是 `N → E → N`，投影完全相同
（`N: a=40,b=40`，`E: a=10,b=10`），差别是两段 `N` 的长度：

| 输入 | `wire-n1` | `wire-n2` | `T=25 ms` | `T=30 ms` |
|---|---|---|---|---|
| reattach | 20 | 20 | 两段都不过 | 都不过 |
| reattach_r2 | 10 | 30 | 一段过一段不过 | 都不过 |

口径 A（相位合并）只看到 `N=40`，在 `T=25`、`T=30` 都会判“过”，
既分不出 20/20 与 10/30，也无法回答“换接前那段是否达标”。
`merge.json`（`N` 段 40/40，中间插 20 ms 的 `E`）在 `T=50` 下口径 A 判 80 过，
分段口径两段都不过——这正是相位合并会把不同接线段**拼成从未连续存在的 80 ms** 的风险。
`rewire_split.json` 则给出“换接后新段落在服务缺口里、重叠为 0”的情形（20 / 0）。

### 4.3 事后改门槛

存下 `o` 之后，任何阈值都可在同一份桶记录上重判，不必回看区间或重放：

| `T` | alpha `o=38` | beta `o=28` | gamma `o=27` | 旧投影 |
|---|---|---|---|---|
| 27 | 过 | 过 | 过（`≥` 取等） | 过 |
| 28 | 过 | 过 | 不过 | 不可判 |
| 30 | 过 | 不过 | 不过 | 不可判 |
| 38 | 过 | 不过 | 不过 | 不可判 |
| 39 | 不过 | 不过 | 不过 | 不过 |

合并窗口同理：alpha `o=134`、beta `o=124`，`T=130` 可精确重判。
由 `a,b,o` 还能直接重算“占在线比”`o/b` 和“占绿比”`o/a`，不需要额外字段。

## 5. 两种留存口径的比较

同一类聚合记录，两种可行键：

- **口径 A（相位合并）**：`(桶, 接线相位, 探头)` → `a, b, o`
- **口径 B（换接分段）**：`(桶, 接线相位)` → `a`；`(桶, 接线相位, 探头, 接线段)` → `b, o`

| 维度 | 口径 A | 口径 B |
|---|---|---|
| 样例行数（alpha/beta/reattach/merge/gaps/windows） | 12/12/2/4/2/1 | 12/12/3/4/2/1（仅换接桶 +1） |
| 合并相邻整桶 | `o` 可加，精确 | `o` 可加，精确 |
| 换接前后分别追问 | 不可分，可能虚增 | 可分 |
| 接回同一相位 | 两段被并成一段 | 保留为两段 |
| 事后改门槛 | 相位级可重判 | 更细可重判 |
| 回到粗口径 | 本身即粗 | 对同一相位/探头求和即可（已断言等价） |
| 是否会拼出未连续时长 | 会（merge：40+40 判成 80） | 不会 |

**建议口径 B**，理由不是精度而是代价几乎为零：在全部样本上它只比口径 A 多 0 或 1 行，
增量上界是“该桶内与该探头相交的接线段数”，与心跳数、到达数无关，仍满足“不交逐条心跳、
到达或区间”的约定。字段上只增加一个接线段标识（输入里已有的 `wiring.id`），不增加时间区间。
若确有硬性体积约束，口径 A 是在“放弃换接前后区分”前提下的退路，但必须同时声明：
它回答不了 4.2 的追问。

字段边界建议：接线段行即使 `b=0` 也保留（区分“接了线但在线为零”与“本桶未接线”）；
某相位有确定绿但没有接线段时，`a` 仍在相位级行里。不要用 `null` 表示零。

## 6. 旧投影仍不可判的情形（即使加了聚合记录也仍有边界）

1. **桶内子窗口**：alpha 桶 `b000` 的 `o=38` 无法给出 `[30,50)` 的值；由总量只能得界 `[8,20]`，
   `T=15 ms` 不可判。固定桶之外的时间窗一律不可判。
2. **连续性 / 最长连续段**：`windows.json` 桶内 `a=30,b=50,o=30`（界收紧到 `[30,30]`，
   重叠总量完全确定），但确定绿被 `E` 切成 3×10 ms，最长连续段只有 10 ms。
   若门槛改问“连续 ≥ T”，任何累计型聚合记录都不够。
3. **到具体到达的归属**：聚合不含逐条到达；`shift-a/b` 说明连确定绿窗的位置都不由投影决定，
   所以“某条到达是否落在绿窗内”仍要回完整产物。
4. **瞬时接线归属**：分段记录能回答“本桶内该接线段上有多少重叠”，但不能回答
   “12.5 ms 那一刻接的是哪个相位”。
5. **网格假设**：入口接受重叠/有缝/不等宽桶，求和前必须显式校验“固定 50 ms 且互不重叠地铺满”，
   否则会重复计数或漏计。
6. **边界与零值**：桶是半开 `[lo,hi)`，门槛按 `≥`；“未接线”与“在线为零”必须可区分，
   且不得把缺失当 `null`、把 `null` 当零。

## 7. 范围声明

- 不重发历史：本文只建议下一版新增记录；已发布版本保持原状，不回填、不重算。
- 不改接口：未修改 `greenbook/`、未新增 CLI 命令、未写入仓库内 SQLite；
  `retention/check.py` 只调用现有 `preview`，发布/回放验证写在 `/tmp` 的临时库里。
- 操作提示：若把新字段并入现有结果产物，会改变 `result_sha256` 并使旧版 `replay` 失配；
  建议以“同版内可由 `services`/`coverage` 确定性重算的旁路聚合”存放，或在新 schema 版本里
  显式分区，而不改写旧版结果。

## 8. 复现

```sh
python3 -m greenbook preview retention/alpha.json
python3 -m greenbook preview retention/beta.json
python3 -m greenbook preview retention/gamma.json
python3 -I retention/check.py          # 打印 A–G 各节并跑断言
```

样本文件：`alpha`/`beta`/`gamma`（主见证对 + 下界见证），`shift-a`/`shift-b`（services 侧见证），
`reattach`/`reattach_r2`/`rewire_split`（换接与接回），`merge`（相邻整桶），
`gaps`（同窗多心跳片段，`o < min(a,b)`），`windows`（桶内多段绿，累计对但连续段短）。
