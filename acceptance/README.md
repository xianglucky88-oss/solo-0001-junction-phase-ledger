# 报表改版绿灯率验收（输入 → 预览 → 发布 → 读回）

本目录是一套**不依赖生产输出作为预期**的手算夹具验收。预期值全部在
`expected.py` 中由数据契约（`../PROJECT_SPEC.md`）纸算得到；生产包
`greenbook/` 在整个过程中不做任何修改，回归只在验收进程内临时注入并立即还原。

运行：

```sh
python3 -I acceptance/run_acceptance.py
```

## 一对夹具（合法、单路口、走廊、可手算）

两个夹具的控制器、接线、到达时刻、报表桶完全相同，只有心跳内部区间不同：

| 文件 | 心跳内部区间（已扣除探头 ±1 ms 误差） | 关系 |
| --- | --- | --- |
| `fixtures/corridor_a_abutting.json` | `[21,140) [140,280) [280,560) [560,720)` | 相邻拼接，只在一点相接，无重叠 |
| `fixtures/corridor_b_overlap.json`  | `[21,140) [138,280) [280,560) [558,720)` | 各有 2 ms 重叠，**并集与 A 完全相同** |

控制器误差为 0，服务区间精确且半开：

```
seq0 N [100,200) | seq1 E [200,300) | seq2 N [300,400) | seq3 E [400,500)
```

同一探头 `loop-*` 的五个到达时刻分别压在不同几何点上：

| 到达 | tick | 判读区间 | 落点 | 正确判定 |
| --- | --- | --- | --- | --- |
| `a-far-green` | 150 | `[149,151]` | 远离一切边缘，N 服务内、N 接线 | green |
| `a-service-edge` | 199 | `[198,200]` | 右端**恰好**等于服务边缘 200 | ambiguous_service（半开右端不算入） |
| `a-splice` | 280 | `[279,281]` | 跨 ha2/ha3（hb2/hb3）拼接点，E 服务内、N 接线 | not_green，须两条心跳共同支持 |
| `a-far-red` | 250 | `[249,251]` | 远离边缘，E 服务内、N 接线 | not_green |
| `a-bucket-edge` | 380 | `[379,381]` | 事实正确为 green，但右端 381 越过主桶 `[50,380)` 的半开右端 | 事实 green；主桶只沾边，排除在分子/分母外 |

`a-service-edge` 取 tick 199 而非 200 是刻意的：tick 200 的区间是 `[199,201]`，
闭区间与半开两种约定都会判歧义，无法区分回归；只有右端恰好落在 200 的
`[198,200]` 才能让"把闭区间右端算进半开服务"翻成误判 green。

## 手算关键值

- 主桶 `[50,380)`、N 相位：green=1，not_green=2（far-red、splice），
  边界/歧义 2 个（bucket-edge、service-edge），绿率 **1/3**，观察时长 **330 ms**。
- 宽桶 `[0,900)`、N 相位：bucket-edge 此时完整落入，green=2、not_green=2，
  绿率 **1/2**；N 观察 **429 ms**，E 观察 **270 ms**。
- 每个 N 相位起点各成一个完整周期：
  - 周期1 `[100,300)`：绿率 **1/3**，N 观察 A=200 / B 朴素 202；
  - 周期2 `[300,500)`：仅含 bucket-edge（green），绿率为整数 **1**，
    N 观察 150、E 观察 50（两夹具相同）。
- 重叠夹具 B 若朴素求和会得到 332 / 431 / 272 / 202，比正确并集各多 2 ms；
  夹具 A 的心跳只相接不相叠，朴素求和与并集相等，因此**该回归在 A 上不可见**。

## 三类回归与判定的对应关系

回归均在 `run_acceptance.py` 进程内通过替换函数注入，结束即还原：

| 变体 | 注入方式 | 预期翻转（其余探针必须保持 PASS） |
| --- | --- | --- |
| R1 闭区间右端算进半开服务 | `observed.inside` 改为 `p1 <= hi` | `a-service-edge` 由 ambiguous 变 green；主桶 1/3→**1/2**，宽桶 1/2→**3/5**，周期1 1/3→**1/2**。命中 R1-facts、R3-main/wide/cycle |
| R2 重叠心跳当额外在线时间 | `workflow.duration` 改为朴素求和 | 仅夹具 B 的四个观察时长探针翻转（330→332、429→431、270→272、200→202）；夹具 A 全绿，事实与绿率完全不动 |
| R3 事实正确但发布端混入歧义分子 | `workflow.summarize` 把沾边/歧义事实塞进绿灯分子 | 主桶 1/3→**3/5**、宽桶 1/2→**3/5**、周期1 1/3→**1/2**；到达事实层全部保持正确 |

R1 与 R3 在主桶上的不同结果（1/2 vs 3/5）使两类回归可区分：R1 只污染
service-edge 一个事实，R3 把 service-edge 与 bucket-edge 两个边界项都计入分子。
脚本末尾的 "Prediction correspondence" 与 "R2 fixture discrimination"
两段会逐行核对实际失败探针集合是否与纸算预测**完全相等**。

## 端到端链路

`E2e-cli` 探针经真实子进程跑完整 CLI（用 `-P` 并显式指定 `PYTHONPATH`，
避免把当前目录隐式塞进模块路径）：

- `preview` 结果等于进程内重算；
- `publish` 写入的 source/result SHA-256 与本地手算摘要一致，重复版名被拒（退出码 2）；
- `show` / `source` / `replay` 读回内容分别等于成果、封存输入、重算成果；
- `history` 版名与摘要与发布回执一致；
- `examples/invalid.json` 必须退出码 2 且不产生库文件。
